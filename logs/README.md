# logs/ —— 全部实测日志

**这个目录是文档里所有数字的证据来源。** `docs/` 下的任何性能/精度数字，
都应该能在这里找到对应的原始输出；`tools/check_docs.py` 会按文件名去核对。

## 命名约定

`<前缀>_<对象>_<版本>[_<条件>].txt`

| 前缀 | 含义 | 例子 |
|---|---|---|
| `board_` | 板端实测（开机自检、对话、工具、压测） | `board_baseline_lut.txt`（板上精度基线）、`board_v3_19b6_stress32.txt`（32 轮压测） |
| `pc_` | PC 引擎（32 题矩阵、多轮套件、基准） | `pc_kv_suite32_v3_19b6_q2b8.txt`（27/27+4/4） |
| `esp32_` | 串口交互脚本的输出 | `esp32_multi.txt`、`esp32_chat_bench.txt` |
| `v3` / `v2` | 训练与导出日志 | `v3_19_pc4_train.txt` |
| `phone_` | 手机端（Termux / Android） | — |
| `teacher_` / `ninfer_` | 教师服务与蒸馏生成 | `ninfer_teacher_v40.err.log` |

## 两个常被引用的基线

- **`board_baseline_lut.txt`** —— 板上精度基线：开机自检（mmap 带宽、双核 GEMV 加速比）、
  多轮对话原文。改动引擎后要与之**逐字对比**回复（见根 `AGENTS.md` §7 验收清单）。
- **`pc_kv_suite32_*.txt`** —— PC 32 题矩阵（27 短任务 + 4 长文召回），
  是 C23/C++ 引擎、CUDA 后端、采样器改动的**逐字节一致性基准**。

## 注意

- 日志是**只增不改**的实测记录，不要为了"让文档对得上"去编辑它；
  对不上说明代码或文档有一边错了。
- `.log`（服务端原始输出）与 `.txt`（脚本整理后的结果）并存；
  `.log` 可能有 GBK/UTF-16 混编，读的时候注意编码。
