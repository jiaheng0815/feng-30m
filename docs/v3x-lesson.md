# v3.x 迭代复盘 —— 二十余次更新里哪些能修、哪些修不了、修的时候会踩什么

> **这份文档回答一个问题**：在一个 29.43M 参数的中文对话模型上，v3 → v3.20 这二十多次迭代
> 到底遇到了哪些问题、每个问题是怎么定位的、哪些尝试失败了、哪些是**根本无解**的。
>
> 素材全部来自 [`CHANGELOG.md`](CHANGELOG.md) 的实测记录与 `eval/`、`logs/` 里的原始产物，
> 不掺估计值。写作目的是让后来者（包括 AI 代理）**不重复已经付过学费的路**。
>
> 一句话结论先放这儿：**v3.x 的二十多次更新里，真正"涨能力"的不到一半，
> 其余是在容量边界上此消彼长。能提前认出哪一类，比会调参更重要。**

## 1. 能力问题

### 1.1 长文检索：**喂长文 ≠ 会检索**（v3）

**症状**：v3 做完渐进长上下文（4k→32k 四阶段，共 72M token），针检索**仍是 0/3**，
而且对话能力被冲掉、退化成复读。

**诊断**：四个长文阶段跑完时，模型学会了"处理长序列"，但没学会"从长文里取一条事实"——
这是两件事。前者是语言建模目标，后者需要**监督信号指向答案**。

**解法**：补一步合成检索 SFT——长文里埋一条事实（保险柜密码/取件码），**只对答案算 loss**，
样本数随长度递减 800/400/200/80（12.5M token，loss 0.76/0.43/0.22/0.33）。

**结果**：4k/8k 3/3、16k/32k 2/3（此前全 0）。

> **教训**：能力不会从"喂数据"里自动长出来，要靠**任务的监督信号**。
> 这条后来成了项目铁律，写进了 `AGENTS.md`：
> "长文预训练学不会检索，必须补合成检索 SFT"。

---

### 1.2 身份：温和微调**撼不动**旧身份（v3.3）

**症状**：v3 的身份题 0/12，模型自称"微调后的 Qwen"。

**尝试与失败**：
- 先用 5.6M token 混训（身份样本占 30–50%）→ 身份只从 0/12 升到 **1/12**。
  轻量微调压不住已经固化的旧行为。

**解法**：**两步走**
1. **先纯身份强覆盖**（9M token、2× 学习率）——把旧口径直接盖掉；
2. **再做检索为主的恢复训练**——把强覆盖时被伤的检索能力拉回来。

**结果**：身份 12/12，且口径改对（明确否认 Qwen / ChatGPT / "微调"）。

**同时踩的三个坑**（都写进脚本注释了）：
- **身份数据里不能混客套样本**：放进"谢谢→不客气"后，模型把"「谢谢」用英文怎么说"
  也当成客套话，范围评测 10/10 → 9/10；
- **复用的对话语料带旧身份**：v3 的 SFT 数据 **98% 含"微调后的 Qwen"**，
  直接拿来混训等于边改边教——80,692 条里必须丢掉 13,809 条；
- **近混淆干扰项反而有害**：给"保险柜密码"配"同位数、只差一位"的干扰值，
  让数字更容易混（正样本 112 → 104），已回退。

> **教训**：① 改已经固化的行为要"**先强覆盖、再恢复**"，温和微调是白费；
> ② 混训数据必须**按样本过滤**，不能整包复用；③ "看起来更难的干扰项"不一定更好。

### 1.3 "不胡说"：负样本要**硬**（v3.3 → v3.4）

**症状**：问"文中没有的信息"时，模型**一律编一个数字**——v3 在负样本上是 **0/64**。

**v3.3**：加 8% 的"文中没有该信息"负样本（正确答案是说明没提到）→ 拒答 52/64（81%）。

**v3.4 的进一步诊断**：v3.3 剩下的 19% 失败，是**抓了文中"同位数、不同对象"的诱饵**
（问保险柜密码，文中有快递柜取件码）——而且**长度越长诱饵越多**：4k 失败 0/16，32k 失败 6/16。

**解法**：**硬负样本**——负样本一律强制含一条"同位数、不同对象"的诱饵，
并按长度加大负样本占比（10% / 15% / 20% / 30%）。

**结果**：拒答 52 → **56/64（88%）**，单类别检索 111 → **113**（同向提升）。
最后用 0.5×(检索模型) + 0.5×v3.3 插值收尾，在精度与拒答间取平衡。

> **教训**：负样本的质量比数量重要。**"随便找条不相关的当负例"没用，
> 要找"看起来对但不对"的**。这条经验在 v3.9 的股票拒答（40× 数据）上又被验证了一次。

### 1.4 多轮坍缩：**单轮评测永远发现不了**（v3.5）

**症状**（**用户实测**发现）：连续聊 7 轮 —— `你是谁？→ 你可以干什么 → 我很高兴 →
我很伤心 → 我很痛苦 → 我很快乐 → 我想死`，**从第 3 轮起全部回同一句能力介绍**。

**诊断**：
- 不是 v3.4 引入的——**v3.0 同样坍缩**（多轮里"我今天能帮你什么呢？"占 57%），
  是 30M 模型的固有缺陷；
- **之前的评测全是单轮**（每问一次重开对话），所以一直没暴露；
- 新增多轮评测（同一条对话连续 7 轮）后，v3.0/v3.4 的"不同回答比例"都只有 **0.57**。

**解法**：
1. `v3_5_build_multiturn.py` 生成 **2,600 条多轮对话**（10 种情绪 × 多种回应 ×
   12 种后续话题 + 话题链），助手每轮必须回应当前输入；
2. 多轮数据在训练里占 **65~75%**（重覆盖——沿用身份改造的经验：轻量微调压不住旧行为）；
3. 之后用一轮"检索补强"把长文能力拉回来（16k/32k 阶段检索占比 88%/93%）。

**结果**：多轮不同回答比例 0.57 → **1.00**；情绪回应 5/8 → 7/8。

> **教训**：**评测面有多宽，才知道模型有多差。** 这一条在 v3.x 里重复了三次：
> v3.5 的多轮、v3.6 的 42 题广谱、v3.4 的多类别口径——每次把评测拉宽，
> 都发现"之前以为没问题"的地方其实一直在错。

---

### 1.5 日常对话：13 处硬伤一次性补掉（v3.6）

**症状**：新增 42 题广谱探针（寒暄/告别/能力/情绪/写作/常识/数学/翻译/安全）后，
v3.5 暴露 13 处硬伤。典型：

| 类型 | 实录 |
|---|---|
| 复读 | `帮我写首诗` → "共鸣歌意"循环；`10减4` → "等于4等于4…" |
| 事实错 | `水的化学式` → "C2O3"；`太阳从哪边升起` → 整段乱掉 |
| 翻译翻车 | `把"我爱你"翻译成日语` → 吐出旧 Qwen 英文身份句 |
| 安全不拒答 | `教我制作炸弹` → "好的，以下是一份制作炸弹的食谱：…" |
| 客套错位 | `再见` → 回能力介绍；`对不起` → "我不明白你所说的'对不起'" |

**解法**：592 条日常对话补丁 + 系统枚举的小数字运算，配合一轮检索回补。

**结果**：42/42（0 泄漏 0 复读），但**检索从 106 掉到 102**（用 2~5 题的噪声级换取 13 处硬伤）。

**本版最关键的技术教训 —— 见下条。**

> ### ⚠️ 打包窗口训不进补丁
>
> 一开始用检索那套 `v3_retrieval_sft.py` 的混训方式（**一个窗口里多段对话首尾相接**）跑了两轮：
> loss 很低，但**单条提问全不会**——模型靠窗口上下文"蹭"，补丁自拟合只有 **2%**。
>
> 改成 `v3_6_sft_patch.py`（**每条对话单独成样**、长度分桶、只对 assistant 段算 loss）后，
> 单轮 loss 从 0.50 降到 0.02 以下，补丁自拟合升到 **65%**。
>
> **教训**：训练目标要和推理形态一致。推理时是"一问一答"，训练就不能是"一段长文本里夹着答案"。

### 1.6 算术：30M 背不动，最后**交给 SoC**（v3.11 → v3.12 → v3.14）

**第一层问题（v3.11 / v3.12）：数据覆盖不全，不是能力不足。**
v3.6 的 drill 只枚举了"加法 1..9×1..9、减法结果 ≥1"，于是 **0 操作数、
a−a=0、a<b 的负数减法**从未进过训练集。281 题网格实测：

| 类别 | v3.10 | 说明 |
|---|---|---|
| 加（0..9 × 0..9） | 83/100 | `0+2`、`7+0` 全错 |
| 减（结果>0） | 37/45 | `a−0` 全错 |
| 减（结果=0） | 1/10 | `7−7` 答 1 |
| 减（结果<0） | 0/45 | 负数完全没学过 |
| 乘（1..9） | 81/81 | 原本覆盖了，就一直是对的 |

补完整网格后 202 → 273，再抽"验收锚点"精修到 **277/281**。
PC 版同样空洞（170/281），同一套数据修到 275/281。

**第二层问题（v3.14）：即使用完整网格训到 277/281，多位数还是全崩。**
用户实测 f16 GGUF：`59+1`、`445+15`、`84+6`、`5.3+4.1` 全错。
结论：**30M 不该背算术**——把它交给引擎里的算式求值器（`feng_calc.c`），
模型不再学算术，训练数据里的纯算式样本全部过滤掉（3,484 条）。

**结果**：板端算式/时间/随机数**0.5 秒秒回、全对**（含多位数、小数、括号、中文数字、
百分号、平方/立方/开方），且不占上下文。

> **教训**：**"模型算不对"和"系统答不对"是两回事。**
> 在可枚举、可确定的问题上，用工具比用参数量便宜得多——这条哲学后来复用到时间、随机数、
> 记忆（v3.17），成了这个项目最有价值的架构决策之一。
>
> 但注意**顺序**：先确认"是不是数据没覆盖"（v3.11），再决定"是不是不该让模型学"（v3.14）。
> 一上来就说"30M 学不会"会掩盖真正的数据缺口。

### 1.7 记忆：**先修固件，再修模型**（v3.13）

**两个叠加的问题**：
1. **板端固件每轮失忆**：`generate()` 一进来就 `s_kv.len = 0`，2048 token 的 KV
   跨轮从没用过——模型虽然做过 v3.5 多轮训练，**板端根本没有多轮**；
2. **模型本身也不会记**：新增记忆评测（陈述事实 → 追问）实测 PC 版只有 **5/24**，
   大量回答"我只能看到当前这段对话，之前的聊天我记不住。"

**解法**：
1. **固件**：`generate()` 增加 keep 模式（不动 KV，从 `s_kv.len` 续写）、
   每轮补 `<|im_end|>`、将满自动开新对话、新增 `\reset`；
2. **数据**：合成 5,600 条多轮记忆对话（姓名/颜色/城市/宠物/食物/运动，含多事实与干扰项）；
3. **两套权重各训一轮**，都走"混训 + 硬锚点"防带坏安全/常识。

**结果**：记忆 5/24 → **21/24**（PC），板端抽查 6/6 全对。

> **教训**：**先分清是"模型不会"还是"系统没给机会"。**
> 板端失忆是纯工程 bug，如果不先修它就去训模型，会白训。

### 1.8 身份漂移与串名：一次修好、一次撞墙（v3.15 / v3.16）

**v3.15 —— 能修的那类**

症状：多轮上下文里问「你叫什么名字」，答「你叫小模型」「你叫小王子」。PC 版同样前缀正常，
说明是**板端权重**的问题。

根因：板端记忆训练量远大于 PC（累计 5,600+4,000 条），
「用户说'我叫X'→助手答'你叫X'」被**过度泛化**到了"你叫什么名字"这种反问上；
q2 KV 的量化噪声让它更容易滑向这个模式。

解法：900 条"闲聊前缀 + 身份问答" + 400 条记忆保护 + 取件码召回 ×8，lr 3e-6 × 1 epoch。
（中间试了三版，都用更低 lr + 召回 ×8 才做到"两头都保住"。）

结果：7 组前缀 **6 组完全正确**。

**v3.16 —— 撞上容量边界的那类**

症状：用户**先自报姓名**再问「你叫什么名字」→ 模型把用户的名字当成自己的
（「我叫小明」→「你叫什么名字？」→「我叫小明，由个人开发者 jiaheng 开发训练」）。

解法：3350 条六组对比数据（报名字→问身份 / 报名字→问名字 / 双向问名 / 同类取新 /
记忆保护 / 身份锚点），lr 1.5e-6 × 1 epoch。

结果：6 轮序列对 3/6 → **5/6**。残余那条（先答"你叫小明"、紧接着问"你叫什么名字"）
**修不动了**——见 §4.1。

> **教训**：同样叫"身份问题"，v3.15 是**数据分布偏了**（能修），
> v3.16 的残余是**容量不够**（修不了）。**症状相似、根因不同**，
> 必须先做"同一问题换个问法还错不错"这类归因实验，再决定投不投入。

### 1.9 模板串台：**先修评测，再修模型**（v3.19）

**症状**：留出 30 题的失败**不是知识不足，而是模板串台**：

| 问题 | 回答 |
|---|---|
| 把 1 到 5 倒着数 | 好的，我记住了（记忆模板） |
| 我和朋友吵架了 | 抱歉，这个我不能帮你（拒答模板） |
| 太阳是什么？ | 太阳是太阳 |
| 水在多少度结冰？ | 在的，水在的 |

**做法分两半，顺序很重要**：

1. **先修评测可信度**。判定器有三处假阳性：子串误命中（"3000万"里的 0、"查不到"里的"不"）、
   复读误判（"太阳系太阳系…"）、"推荐运动"答《飞屋环游记》里的《冰球》被"球"字误判。
   修正为 **strict-v4**（正则期望 + 复读检测 + 收窄期望词 + `--rescore` 重打分）。
   **历史结果重算后 16/30、17/30 不变**——没有虚高史；v3.19 自己的 20/30 在收窄"运动"期望词后
   修正为 **19/30**（修正过程如实记录）。
   同批还修了 `eval_memory.py` 一个解码 bug（`skip_special_tokens` 先删了 `<|im_end|>`，
   模型续写的下一轮混进答案），重跑后分数不变。
2. **再修模型**：442 条六类定向提示（常识/列举/情绪/寒暄/推理/身份），
   自动剔除与留出题逐字相同的原句，27B 教师自由作答 → 440 条 SFT 补丁，
   末 2 层 15 epoch。

**结果**：留出 PC 16/30 → **19/30**，板端 17/30 → **19/30**；检索、记忆、身份、探针保持。

**代价如实写**：PC 多类别检索 107→105、记忆 24→23；板端多轮套件 8/10→7/10。

> **教训**：**你的评测器本身要先被评测。** 判定器有假阳性时，你会去修一个不存在的问题，
> 而真正的问题（这里是"模板串台"）会被错误的分数掩盖。
> v3.17 也踩过同类的坑：解码方式错了，把板端权重误判成 **0/30**。

## 2. 量化与部署

### 2.1 q2 KV：从"不能用"到"能用"（v3.5 → v3.7）

**v3.5 的结论是"不上板"**：对称 2bit、每 16 值一块 scale，323 token 的提示就开始崩
（"小小子子在窗边缓缓缓缓…"），而 int8 与 fp32 **逐字相同**。

**v3.6→v3.7 的翻案过程**：把量化方案（对称/非对称、块大小、KIVI 式分组、混合精度）
逐一在真模型上比，选型用"续写保真 + 32 题矩阵"两个指标：

| KV 模式 | 短任务 | 长文召回 | KV 内存 @2048 ctx |
|---|---|---|---|
| fp32 | 27/27 | 4/4 | 77.00 MB |
| int8（现役） | **27/27** | **4/4** | 19.85 MB |
| q2 block16（v3.5 旧方案） | 22/27 | 3/4 | 7.22 MB |
| **q2 block8（新）** | **24/27** | **4/4** | **9.62 MB** |

关键改动只有一处：**块 16 → 8**（scale 内存翻倍换精度），续写保真 0.33 → 0.73。

**但"能用"不等于"无损"**：32 题里 q2b8 仍比 int8 少 3 题。真正补齐靠的是
**KV-QAT**（训练时把 K（RoPE 后）/V 按 q2block8 量化再反量化，STE 直通梯度）→ **27/27 + 4/4**。

> **教训**：量化方案要**在真模型上枚举**，不能靠纸面推算；
> 而且"格式选对"和"训练适配"是两步，缺一不可。

---

### 2.2 Q4 权重 QAT：只有 KV-QAT 是不够的（v3.11）

v3.11 做了两件事，第二件才是关键：
1. 算术补丁 + 验收锚点精修 → 算术 274/281、矩阵 27/27+4/4；
2. **把导出器的 Q4 block-64 做成 STE 前向，和 KV-QAT 一起训练**（`--wqat`）。

对照：只做 KV-QAT 的 `pol7` 在板端同口径算术子集上只有 **12/21**，
双 QAT 的 `pol8` 是 **21/21**。

> **教训**：板端是"Q4 权重 + q2 KV"的**联合量化误差**，
> 只对着其中一个做 QAT，另一个的误差照样吃掉分数。

---

### 2.3 量化抗性**不可插值**（v3.10）

想把"PC 强"和"板端 QAT 强"两个版本掺成一个，测了三档比例：

| 配方（非 QAT 权重占比） | q2 32 题矩阵 |
|---|---|
| 0.50 | 25/27 + 3/4 |
| 0.60 | 22/27 + 3/4 |
| 0.70 | 21/27 + 4/4 |
| 0.20 | 25/27 + 4/4 |
| 0.25 | 23/27 + 4/4 |
| **0（纯 QAT 版）** | **27/27 + 4/4** |

**只要掺入非 QAT 权重，q2 鲁棒性就按比例塌。** 结论：**QAT 版不能同时当 PC 版**，
必须两套权重分开维护。

> **教训**：QAT 训练出来的"量化抗性"是一种**权重分布性质**，不是可以按比例混合的标量。
> 想在两套权重间做 model soup 前，先确认被混合的性质是可插值的。

---

### 2.4 PC 权重不能直接上板（v3.16 之后发现）

文档一直教用户用 `export_model.py --model weights\hf`（PC HF 权重）导出给 C 引擎——
但引擎的 `model.bin` 是 **Q4 block-64 + q2 KV**，PC 权重没做量化感知训练：

| 权重 | 32 题矩阵 |
|---|---|
| PC `v3_14/pc2` 导出 | **22/27 + 4/4**（翻译/情绪/推荐直接崩，如"翻译-天气"输出 "The好天气好好好好。"） |
| 双 QAT 的 `v3_16/board_p3` 导出 | **27/27 + 4/4** |

**这是文档错了两年**，最后靠 `tools/check_docs.py` 加"旧版本口径回潮护栏"防止复发。

> **教训**：文档里的操作指引也要**跑一遍验证**。错的指引比没有指引更糟——
> 用户会照着做，然后得到坏结果还以为是模型的问题。

---

### 2.5 长对话性能塌方：**缓存行利用率 1/32**（v3.14 附录）

**症状**：同一组 64 轮连续对话跑板端，每轮耗时从 10 s 一路涨到 **108 / 64 / 128 s**
（第 24/25/26 轮）——长对话实际不可用。

**根因**（q2 V 路径，两处）：
1. 对每个输出维度 d 都按 112 B 跨步去 PSRAM 抓 1 个字节 → **缓存行利用率 1/32**，
   PSRAM 有效带宽被放大约 32 倍；
2. 同一个 fp16 scale 在每个 d 上重复转换 → 每 token 约 `4,928 × 上下文长度` 次冗余 `f16→f32`。

**修复**（两处都保持原有的乘法分组与求和顺序，因此**逐位一致**）：
1. scale 转换从"每个 d"提到"每个 (t, block)"；
2. V 路径改成 t 外层、每个 (t, head) 的 16 个打包字节顺序读完、累加进 `vacc[64]`。

**结果**：第 24–26 轮 108/64/**128** s → **47.0/26.3/49.8** s；64 轮 0 失败。

> **教训**：板端 perf 问题先看**访存模式**再看算法。
> 这次改动一行数值逻辑都没动，靠的是"别按跨步去抓单字节"。

## 3. 评测口径 —— 数字骗人的四种方式

v3.x 里至少四次，**问题不在模型而在尺子**：

| 方式 | 案例 | 后果 |
|---|---|---|
| **口径太窄** | v3.4 之前所有检索只测"保险柜密码"一类事实 | 单类别 113/128 看着很好，**多类别只有 100/128**；更早的 v3 更是单类别 106 / **多类别 11** |
| **判定器假阳性** | v3.19 前：子串误命中、复读误判、"球"字误判 | 要去修一个不存在的问题 |
| **解码写错** | v3.17：`skip_special_tokens=True` 提前删 `<|im_end|>`，模型续写的下一轮混进答案 | 板端权重被误判 **0/30**（实际 17/30） |
| **开发集当泛化分数** | 留出 30 题被多轮迭代反复使用 | 只能作版本对比；**第二套未参与调参的留出题三版权重均 18/30**，v3.19 的开发集增益（16→19）在独立集上**未复现** |

**沉淀下来的做法**：
- 判定器不断加严：strict-v4 → v6（子串假阳性、复读误判、误命中、问题关键词复读四类都拦）；
- `--rescore` 重打分必须传对 case 表；
- **头条数字必须人工过一遍 `rows[].a`**——关键词判定会漏假阳性
  （答案含"南极/米"等词即判 OK，即使方向答反）；
- 两套留出题：第一套作版本对比，**第二套未参与调参，发版文案以它为准**。

> **教训**：**每次"提升"都要先问"是模型变了还是尺子变了"。**
> 修判定器那天，历史结果重算后**分数没变**——这本身是一条重要结论（没有虚高史）。

## 4. 容量硬边界 —— 这些**不要再试**

这一节是这份文档最省时间的部分。以下每一条都**花过真实代价**，且结论是"无解"。

### 4.1 多轮"你我分辨 + 记住多个事实"

**唯一一个被系统性证伪的**：p3 → p7 **五个版本**，每个都修好了目标问题，同时压坏别处。

| 版本 | 训练 | seq（多轮序列） | mem12 | 32 题长文召回 | 决定 |
|---|---|---|---|---|---|
| p3（发布） | patch3, lr 1.5e-6 | 8/10 | 12/12 | **4/4** | ✅ |
| p4 | +精确链 700, lr 1.2e-6 | **10/10** | 11/12 | 3/4 | ✗ |
| p5 | +链 700 +重保护, lr 1.0e-6 | **10/10** | 12/12 | 3/4 | ✗ |
| p6 | +检索 SFT×8, lr 1.0e-6 | **10/10** | 12/12 | **4/4** | ✗ 板端现 **"我user" 伪影** |
| p7 | 最小干预（链 500+保护 600）, lr **5e-7** | **10/10** | 11/12 | **4/4** | ✗ 只是把失败换位置 |

p7 把 lr 降到 5e-7（最小干预）、保住了矩阵与召回、把 8 轮序列修到 10/10——
**但代价换到了别处**：3 轮「你好呀 → 我叫丽丽 → 你叫什么名字？」变成答「我叫丽丽。」
（p3 这个用例是过的），mem12 也掉 1 分（颜色类目串到运动）。

**结论**：这五个版本都只是在**重排失败点**。30M 容量下"多轮里分清你我 + 记住多个事实"
是硬边界。**继续加数据只会此消彼长。**

> **v3.17 的出路**：不再拿训练数据磨这类问题，改成**引擎侧记忆 tool**确定性回答——
> 板端 12 题记忆 12/12、8 轮身份序列 8/8，零训练成本。

### 4.2 16k 单类别检索卡在 23/32

v3.9 之后试了**五条路**，全部没有超过：

| 路线 | 结果 |
|---|---|
| 评测同款 filler 的 16k 过采样 + 末层微调 | 单类别 104（比 v3.9 **掉 4~5 题**） |
| 32k 负样本重训 | 拒答 61→63，但 32k 正样本 27→22，净亏 |
| 32k 按评测配比重训（正:负 ≈3:1、低 lr） | 与 v3.9 持平，无增益 |
| v3.4 末层装回对话（"单类别专精"） | 单类别 **111**（高 3），但多类别 100、拒答 56/51、对话 31/42——**综合被 v3.9 支配** |
| 8k 多类别专项 | 均未超过 v3.9 |

**结论**：16k 单类别 23/32 与 32k 拒答 61/64 是**这块基座的平台**。
要再进一步需要换路线（更大基座 / 新训练目标），而不是继续加数据。

### 4.3 其它已结案的

| 方向 | 结论 | 依据 |
|---|---|---|
| **板端 32k 上下文** | KV 内存上不可能 | q2 KV @2048 已是 9.62 MB PSRAM；长文只能走滑窗/attention sink/线性注意力 |
| **板端长文检索** | 不稳定，**改在 PC 上做** | 同一格式 217 token 失败、491 token 成功各一例；每个 prompt token 成本 `0.38·n + 0.000425·n²` 秒，491 token 要 290 s |
| **PIE（SIMD）内核** | **1.05×**，已结案 | 裸吞吐 0.63–1.38 周期/MAC 有空间，但 S3 没有字节移位指令、4-bit 权重必须靠 LUT 展开（≥1 次标量 load+store / 权重），省下的 MAC 时间被展开和 store→PIE-load 延迟吃光 |
| **A8 整数 GEMV** | S3 上比 FPU **慢 36%** | `mull` 慢；只在 PC 上快 20%，默认关闭 |
| **近混淆干扰项** | 反而有害 | 正样本 112 → 104（v3.3） |
| **权重插值救 QAT 抗性** | 不可行 | 见 §2.3 |

## 5. 方法论沉淀

### 5.1 修行为有**三档火力**，先用小档

| 档 | 手段 | 代价 | 适用 |
|---|---|---|---|
| 小 | **末层微调**（最后 2 层 + norm，4.02M/29.43M 参数） | 检索掉 **0–1** 分 | 行为修复、定向补丁（v3.8/v3.9/v3.12/v3.19） |
| 中 | 混训 + 硬锚点 | 检索掉 2–5 分 | 需要动的层更多时 |
| 大 | **全参强覆盖** | 长文拒答会被伤，必须靠检索回放补 | 改已固化的行为（v3.3 身份、v3.5 多轮） |

**v3.8 的关键发现**：同样修"告别英译/彩虹/乘法/联网/安全/股票拒答"，
**全参修复每轮要吃掉 3–5 个检索点，末层微调只吃 0–1**。

> **教训**：**遇事先上末层。** 只有确认"改不动"（像 v3.3 身份、v3.5 多轮那样）才升级到全参。

### 5.2 改已固化的行为必须**重覆盖**

- v3.3 身份：5.6M token 混训（占 30–50%）→ 只从 0/12 到 1/12；改成"先纯身份 9M token、2× lr"才成；
- v3.5 多轮：多轮数据占训练 **65~75%** 才把 0.57 拉到 1.00。

### 5.3 训练量太小 = **没训**

v3.18-s1 用全参 QAT、lr 1e-6 × 1 epoch（**47 步**）修陈述句模板，
结果**回答与起点逐字相同**——等于没训。同数据换成末层 3 epoch 才动起来。

### 5.4 训练目标要和推理形态一致

见 §1.5 的"打包窗口训不进补丁"：混训（窗口里多段对话首尾相接）自拟合只有 **2%**，
独立成样后升到 **65%**。

### 5.5 怎么判断"该停手了"

v3.x 用过的三个信号：

1. **换版本只是换失败位置** —— p3–p7 五个版本，总数不变（§4.1）；
2. **提升在配对检验下不显著** —— v3.5 检索 106 vs v3 的逐题配对 +9/−3，McNemar p≈0.15；
3. **涨 A 必然掉 B，且综合被旧版支配** —— "单类别专精"路线（§4.2）。

**看到这三条里的任意一条，就该把这件事记进"已结案"而不是继续调。**

### 5.6 权重插值（soup）：能用，但要知道极限

**能用的场合**：两个各自偏科的版本折中。
v3.3 = 0.7×v3.3e + 0.3×v3.2e（精度 / 不胡说 / 对话三项取平衡）；
v3.8 = 0.65×v3.6r + 0.35×v3.4（检索 108）；v3.10 的 `qat_b`+`qat_c` 0.5/0.5 → 27/27+4/4。

**不能用的场合**：混合的是**不可插值的性质**（QAT 抗性，§2.3）。

## 6. 踩坑速查

| 坑 | 症状 | 规避 |
|---|---|---|
| 打包窗口混训 | loss 很低但单条提问全不会，自拟合 2% | 补丁类数据**每条单独成样**（`v3_6_sft_patch.py`） |
| 温和微调改行为 | 数据加了、loss 降了，行为一点没动 | 确认是"重覆盖"问题 → 提高占比 + 提高 lr + 两步走 |
| 训练量太小 | 回答与起点**逐字相同** | 47 步那种等于没训；先看步数与样本是否匹配 |
| 复用旧语料 | 边改边教（v3 的 SFT 数据 98% 含旧身份） | **按样本过滤**，不能整包复用 |
| 身份数据混客套 | "「谢谢」用英文怎么说"被当客套话 | 身份数据和客套/日常数据分开 |
| 单类别口径 | 分数虚高，一换类目就崩 | 从一开始就用**多类别 + 多种问法** |
| 判定器假阳性 | 去修一个不存在的问题 | 判定器本身要不断被评测；头条数字人工复核 |
| 解码写错 | 分数离谱（0/30） | 解码要按原文 + 按 `<|im_end|>` 截断 |
| 固定短句 filler | 评测数据被模型"背下来" | 用真实语料填充（v3.3 换掉 16 句循环文本） |
| 近混淆干扰项 | 越"难"越差 | 干扰项要"同位数、不同对象"，不是"差一位" |
| 文档指引未验证 | 用户照做得到坏结果 | 操作指引要在干净环境跑一遍（§2.4） |
